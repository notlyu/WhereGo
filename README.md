# Куда пойти

Закрытое веб-приложение для двоих: места Петербурга, которые хочется посмотреть,
и походы, которые уже случились.

ТЗ живёт в Obsidian: `Obsidian-Куда-пойти/Projects/Куда пойти`.
Дизайн перенесён из прототипа `Прототип мест Санкт-Петербурга/`. Макетов там
**два, и они разные** — `Куда пойти.dc.html` (телефон) и `Куда пойти - десктоп.dc.html`.
Второй не сводится к растянутому первому, см. «Два макета» ниже.

## Что сделано

**Этап 1 — каркас и места.** Вход, лента с фильтрами и тремя видами, карточка
места, форма создания и правки, справочник категорий, смена статуса, выход.
Экраны этапов 3–5 заведены заглушками, чтобы навигация была целой.

Этапы 2–5 (фото, отзывы, карта, свайпы, планы, история, PWA) — впереди.

## Запуск

```bash
pnpm install
pnpm dev
```

Нужен Node **20.19+ или 22.12+** (нижняя граница задана Vite 7) и pnpm 10.
Если `corepack` подставляет pnpm 11 и тот ругается на версию Node:

```bash
corepack prepare pnpm@10.18.0 --activate
```

### Без Supabase

Пока в окружении нет `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`, приложение
работает на локальных демо-данных в `localStorage` — 19 мест Петербурга и
4 идеи из прототипа. Экраны можно открыть и потрогать до того, как заведён
бэкенд.

Демо-вход: `stas@example.com` или `alina@example.com`, пароль `demo1234`.
Сбросить данные — кнопка в профиле.

### С Supabase

Пошагово, с указанием где какая команда вводится — **[SETUP.md](SETUP.md)**.

Коротко: создать проект → применить `supabase/migrations/0001_init.sql` →
отключить публичную регистрацию → завести два аккаунта → положить URL и **anon**
ключ в `.env.local` → `pnpm types:gen`.

Приложение переключится на боевой бэкенд само, менять код не нужно.

## Устройство

```
src/
├── api/          ← ЕДИНСТВЕННОЕ место обращений к бэкенду
│   ├── backend.ts    контракт
│   ├── supabase/     боевая реализация
│   └── local/        localStorage + сидовые данные
├── components/   ui/ · layout/ · place/
├── features/     экраны по маршрутам
├── hooks/        auth, react-query, фильтры, черновик формы
├── lib/          cn · формат дат · геометрия
├── styles/theme.css  токены дизайна
└── types/        database.ts (генерируется) · models.ts (домен)
```

Развёртывание — `wrangler.jsonc`: Cloudflare Worker со статикой, SPA-роутинг
через `not_found_handling`. Файла `public/_redirects` тут нет намеренно, см.
[SETUP.md](SETUP.md), шаг 10.

### Правило изоляции

Прямые вызовы Supabase вне `src/api/` запрещены и ловятся ESLint-правилом
`no-restricted-imports`. Это единственное, что делает возможной замену бэкенда
без переписывания приложения — и ровно поэтому локальный бэкенд получилось
подставить одной строкой в `src/api/index.ts`.

## Что осталось сделать по Этапу 1 (вне кода)

- [ ] Создать проект Supabase и применить миграцию
- [ ] **Отключить публичную регистрацию** (А-2)
- [ ] Завести два аккаунта, проверить срабатывание триггера профилей
- [ ] Подключить репозиторий к Cloudflare Pages
- [ ] **Настроить UptimeRobot** на URL Supabase, интервал 5 минут

Последние два — те самые пункты, без которых этап не считается закрытым.
Проект на бесплатном тарифе засыпает через 7 дней без запросов и поднимается
только руками из дашборда.

## Два макета

Телефон и десктоп в прототипе устроены по-разному, поэтому это не один экран
с медиазапросами, а две вёрстки поверх одних данных (`useFeedData`,
`selectPlaces`, `useFilters`). Выбор — `useIsDesktop()`, рендерится только одна:
отрисовать обе и спрятать лишнюю через `hidden` значит удвоить DOM и оставить
скринридеру две копии ленты.

| | Телефон (< 900px) | Десктоп (≥ 900px) |
|---|---|---|
| Навигация | пилюля снизу, 4 вкладки | панель слева 252px, 7 пунктов со счётчиками |
| Лента | горизонтальные полки по категориям | сетка `auto-fill minmax(300px, 1fr)` |
| Фильтры | нижняя шторка | панель, раскрывается под заголовком |
| Идеи | сегмент «Места / Идеи» в ленте | свой пункт меню и свой экран |
| Место | одна колонка, обложка 300px во всю ширину | две колонки, справа липкая, обложка 420px |
| Форма места | одна колонка | две колонки, max-width 860px |
| Поверхности карточек | `#1E1E1E` | `#161616` |
| Выбранный чип | акцентный зелёный | белый |

Маршрут у идей один — `/ideas`. На телефоне сегмент в ленте просто переходит
на него, поэтому «назад» из идеи ведёт куда ожидается, а ссылкой на идеи можно
поделиться.

**Разделы, не поместившиеся в четыре вкладки** (Планы, «Мы были тут», Итоги
года, Идеи), на телефоне лежат списком на экране профиля — ровно как в макете.
Без этого списка половина приложения с телефона недостижима.

## Расхождения с прототипом

| Место | Прототип | Здесь | Почему |
|---|---|---|---|
| Вход | инвайт-код | email и пароль | А-1; аккаунты заводятся вручную, регистрация закрыта |
| «кто хочет» | «хотим оба» по свайпам | автор места со статусом `want` | голоса появятся на Этапе 4 (В-1, В-2) |
| Фото | заглушки-штриховка | они же | загрузка в R2 — Этап 2 (Ф-1…Ф-6) |
| Расстояние | «2,4 км» в карточке | не показывается | нужна геопозиция и координаты — Этап 3 (М-13) |
| Отзывы на десктопе | две карточки под фото | текст-заглушка | О-1…О-7 — Этап 2 |
